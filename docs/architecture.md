# Architecture & security

## Components

| Component | Runs where | Reachable from | Notes |
|---|---|---|---|
| **Ollama** (`ollama` container) | Desktop, GPU via NVIDIA Container Toolkit | **Only** other containers on the compose network | No host port is published. Your laptop can never reach it directly. |
| **Open WebUI** (`open-webui` container) | Desktop | `127.0.0.1:3000` on the desktop; the `tailscale` container | Auth is always on, public sign-up is off, and new accounts default to `pending`. |
| **Tailscale** (`tailscale` container, userspace mode) | Desktop | Devices signed in to **your** tailnet | Serves `https://ai-desktop.tailXXXXXX.ts.net` → `http://open-webui:8080`. Funnel is explicitly disabled. |
| **WSL keepalive** (Windows scheduled task) | Desktop, Windows side | n/a | Starts WSL at boot (before sign-in) and holds it open. |

**From the laptop you can reach exactly one thing:** Open WebUI over HTTPS, via Tailscale, and only after signing in. Everything else stays private to the desktop.

## Request path

```
Laptop browser
  └─ https://ai-desktop.tailXXXXXX.ts.net   (WireGuard-encrypted, tailnet members only, TLS cert from Let's Encrypt via Tailscale)
       └─ tailscale container: Tailscale Serve reverse proxy
            └─ http://open-webui:8080        (Docker network, never leaves the host)
                 └─ http://ollama:11434       (Docker network)
                      └─ RTX 4060 Ti (CUDA via WSL2 / native driver)
```

## Network exposure (verified 2026-10-01)

- WSL listeners: only `127.0.0.1:3000` (Open WebUI). Nothing on `11434`.
- Windows: `localhost:3000` is forwarded by WSL (`wslrelay`) on loopback only. The desktop's LAN IP `<LAN-IP>:3000` was **not reachable**.
- `tailscale serve status` shows `(tailnet only)`. Funnel is off, and `AllowFunnel: false` is set in `serve.json`.
- **No firewall rules were added or changed.** The Tailscale container only makes outbound connections (userspace networking, so it needs no tun device and no `NET_ADMIN`).
- No router port forwarding.

## Authentication

- `WEBUI_AUTH=True`. This must never be turned off while the UI is reachable over the tailnet.
- `ENABLE_SIGNUP=False`. Only the very first account (created locally on the desktop, before Tailscale was connected) could register, and it became admin.
- `DEFAULT_USER_ROLE=pending`. Even if sign-up is ever re-enabled, new users can't chat until the admin approves them.
- `WEBUI_SECRET_KEY` signs sessions. It's random, generated by `scripts/init-env.sh`, and stored only in `.env` (mode 600).
- Tailscale is a second, independent gate: a device must be in your tailnet before it can even see the login page.

## Secrets: where they live

| Secret | Location | In git? |
|---|---|---|
| `WEBUI_SECRET_KEY` | `.env` | No |
| Open WebUI users and password hashes | `open-webui` Docker volume | No |
| Tailscale node key / login | `tailscale-state` Docker volume | No |
| Tailscale account login | your browser (interactive login, no auth key stored) | No |

## Why these choices

- **Docker Engine in WSL, not Docker Desktop.** It starts at boot without a Windows sign-in, and it's the same stack you'll run on native Ubuntu.
- **Tailscale as a container, not on Windows.** The whole system is one compose file. Moving to Ubuntu needs no Windows-specific networking, and Serve talks to Open WebUI over the internal Docker network.
- **Userspace Tailscale.** No kernel privileges are needed. Serve (an inbound proxy) works fully in this mode.
- **Ollama with no published port.** The model API has no authentication of its own, so it simply isn't reachable from outside the compose network.
