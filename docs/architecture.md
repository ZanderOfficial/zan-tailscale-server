# Architecture & security

## Components

| Component | Runs where | Reachable from | Notes |
|---|---|---|---|
| **Ollama** (`ollama` container) | Desktop, GPU via NVIDIA Container Toolkit | Containers on this host (compose network, plus `172.17.0.1:11434` on the Docker bridge for OpenHands sandboxes) | Not reachable from the LAN, the tailnet or Windows. Your laptop can never reach it directly. |
| **Open WebUI** (`open-webui` container) | Desktop | `127.0.0.1:3000` on the desktop; the `tailscale` container | Auth is always on, public sign-up is off, and new accounts default to `pending`. |
| **OpenHands** (`openhands` container) | Desktop, mounts the Docker socket | `127.0.0.1:3001`; `oh-gate` | Repo-based coding agent. Starts one **sandbox** container per session (host network, ports 8000/8001/8011/8012). No login of its own. |
| **oh-gate** (`oh-gate`, Caddy) | Desktop | Only the `tailscale` container (fixed IP on the `edge` network) | The auth layer for OpenHands: passes only requests carrying **your** `Tailscale-User-Login`. |
| **Tailscale** (`tailscale` container, userspace mode) | Desktop | Devices signed in to **your** tailnet | Serve: `:443` → Open WebUI; `:8443` → oh-gate → OpenHands; `:8000/8001/8011/8012` → oh-gate → active sandbox. Funnel is explicitly disabled. |
| **WSL keepalive** (Windows scheduled task) | Desktop, Windows side | n/a | Starts WSL at boot (before sign-in) and holds it open. |

**From the laptop you can reach exactly two things**, both over HTTPS via Tailscale only: Open WebUI (after signing in) and OpenHands plus its active sandbox (only as your Tailscale identity). Ollama, the OpenHands app port, and everything else stay private to the desktop.

## Request path

```
Laptop browser
  └─ https://ai-desktop.tailXXXXXX.ts.net   (WireGuard-encrypted, tailnet members only, TLS cert from Let's Encrypt via Tailscale)
       └─ tailscale container: Tailscale Serve reverse proxy
            └─ http://open-webui:8080        (Docker network, never leaves the host)
                 └─ http://ollama:11434       (Docker network)
                      └─ RTX 4060 Ti (CUDA via WSL2 / native driver)
```

## Network exposure (verified 2026-10-01, updated 2026-10-02)

- WSL listeners: `127.0.0.1:3000` (Open WebUI), `127.0.0.1:3001` (OpenHands), `172.17.0.1:11434` (Ollama, Docker bridge only). While a session is active, the sandbox listens on 8000–8012 inside WSL. WSL's NAT keeps these off the LAN; on native Ubuntu, firewall them.
- Windows: `localhost:3000` is forwarded by WSL (`wslrelay`) on loopback only. The desktop's LAN IP `<LAN-IP>:3000` was **not reachable**.
- `tailscale serve status` shows `(tailnet only)`. Funnel is off, and `AllowFunnel: false` is set in `serve.json`.
- **No firewall rules were added or changed.** The Tailscale container only makes outbound connections (userspace networking, so it needs no tun device and no `NET_ADMIN`).
- No router port forwarding.

## Authentication

- `WEBUI_AUTH=True`. This must never be turned off while the UI is reachable over the tailnet.
- `ENABLE_SIGNUP=False`. Only the very first account (created locally on the desktop, before Tailscale was connected) could register, and it became admin.
- `DEFAULT_USER_ROLE=pending`. Even if sign-up is ever re-enabled, new users can't chat until the admin approves them.
- `WEBUI_SECRET_KEY` signs sessions. It's random, generated by `scripts/init-env.sh`, and stored only in `.env` (mode 600).
- Tailscale is a second, independent gate: a device must be in your tailnet before it can even see the login page.
- **OpenHands** has no login of its own. `oh-gate` admits only requests from the tailscale container's fixed IP that carry `Tailscale-User-Login: <TS_ALLOWED_LOGIN>`. Tailscale Serve sets that header from the authenticated device owner, and clients can't forge it. `verify.sh` confirms that requests with no header, and requests with a forged header from another container, both get 403.

## Secrets: where they live

| Secret | Location | In git? |
|---|---|---|
| `WEBUI_SECRET_KEY` | `.env` | No |
| Open WebUI users and password hashes | `open-webui` Docker volume | No |
| Tailscale node key / login | `tailscale-state` Docker volume | No |
| Tailscale account login | your browser (interactive login, no auth key stored) | No |
| GitHub token (for OpenHands) | `openhands-state` volume, entered in the OpenHands UI | No |
| `TS_ALLOWED_LOGIN` (your Tailscale email) | `.env` | No |

## Why these choices

- **Docker Engine in WSL, not Docker Desktop.** It starts at boot without a Windows sign-in, and it's the same stack you'll run on native Ubuntu.
- **Tailscale as a container, not on Windows.** The whole system is one compose file. Moving to Ubuntu needs no Windows-specific networking, and Serve talks to Open WebUI over the internal Docker network.
- **Userspace Tailscale.** No kernel privileges are needed. Serve (an inbound proxy) works fully in this mode.
- **Ollama on the Docker bridge only.** The model API has no authentication of its own, so it's published only on `172.17.0.1`, which OpenHands sandboxes need and nothing outside this host can reach.
- **Identity-based gate for OpenHands.** The browser connects to several ports (the app and the sandbox), including websockets. A password proxy would prompt per port and break websockets, so the Tailscale identity header gives seamless and unforgeable auth instead.
